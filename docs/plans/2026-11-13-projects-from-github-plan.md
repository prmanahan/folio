- **G1, blocks R-15's acceptance criterion (held in T6 and T8). Disposition: level 3, held for Peter.**

  **The finding.** R-15's acceptance criterion says: "no verb (GET, POST, PUT, DELETE) on any removed path returns `application/json`". On the trunk, every unmatched `/api/*` path is answered by `api_not_found` in `libs/site-core/static_files.rs`:
  - routes `/api`, `/api/` and `/api/{*rest}`;
  - the answer is `AppError::NotFound`, which renders `Json({"error": …})` with a 404 (`libs/site-core/error.rs:77-78`).

  The test `unknown_api_paths_return_a_json_404_not_the_index_page` (`libs/site-core/tests/test_build_app_security.rs:396`, #4718) pins that behaviour. Once the routes are removed, each removed path answers `application/json`, so the criterion cannot pass without reversing #4718. R-15 does not authorize that.

  **Options:**
  - **(a)** Amend the criterion to key on the outcome: every verb on a removed path returns the API-miss 404 (`{"error":"Not found"}`) and no project data.
  - **(b)** Amend it to "never 2xx".
  - **(c)** Change the API fallback. This reverses #4718 and is out of scope.

  **Recommendation (recorded by the lead, awaiting Peter): (a).** Amend R-15's criterion to "returns the API-miss 404 `{"error":"Not found"}` and no project data". This is a locked-text amendment for the spec author. *P-LockContract:* "A lock binds the implementation, not the facts: where later work has falsified what the locked text says, raise it rather than ship it unchanged." T8 is held for Peter anyway.
